# كَحيل مواعيد — حدود الاستقلال والربط

## القرار المعتمد

`كَحيل مواعيد / KAHEEL Appointments` منتج مستقل وظيفيًا داخل المستودع الأساسي
`1127410650/KAHEELProject` وقاعدة Supabase الأساسية `rgpnhzovtceitqxpiilf`.

وجوده في المستودع والقاعدة نفسيهما في المرحلة الحالية يحقق تسجيل دخول موحدًا وتشغيلًا أبسط،
لكن تصميم الحدود يسمح بفصله إلى تطبيق ومستودع وقاعدة مستقلة لاحقًا دون نقل منطق سوق كَحيل إليه.

## حدود البيانات

- جميع جداول ودوال وسياسات المواعيد تبدأ بالبادئة `appt_`.
- لا توجد مفاتيح أجنبية من `appt_*` إلى أي جدول `mkt_*`.
- لا تقرأ دوال المواعيد أي جدول `mkt_*` ولا تكتب فيه.
- الهوية المشتركة الوحيدة هي `auth.uid()` من Supabase Auth.
- تغييرات المواعيد لا تعدل بيانات السوق أو إعلاناته أو منشآته أو حجوزاته السابقة.

## الربط المستقبلي

الجدول `appt_market_links` هو عقد الربط الاختياري الوحيد. يحفظ معرفات خارجية أو رابطًا
ومسارًا كنصوص/UUID غير مرتبطة بمفاتيح أجنبية. لذلك يمكن لاحقًا:

1. نقل جداول `appt_*` إلى قاعدة مستقلة.
2. الإبقاء على تسجيل دخول موحد عبر مزود هوية أو SSO.
3. استبدال `appt_market_links` بواجهة API أو أحداث تكامل.
4. تشغيل زر «اذهب إلى سوق كَحيل» من متغير البيئة `VITE_KAHEEL_MARKET_URL`.

## حدود الواجهة

- كل منطق الواجهة موجود تحت `src/appointments/`.
- ملف المسار `src/routes/appointments.tsx` مجرد نقطة تركيب صغيرة.
- لا تستورد وحدة المواعيد ملفات `mkt-*` أو مكونات السوق الخاصة.
- تستخدم فقط البنية العامة المشتركة: Supabase client، الجلسة، الترجمة، ومكونات UI الأساسية.

## الأمان

- RLS مفعّل على جميع جداول `appt_*`.
- القراءة العامة محصورة في مقدمي الخدمة المنشورين وخدماتهم وأوقاتهم العامة.
- العميل يرى مواعيده وأدواره فقط.
- مقدم الخدمة يرى ويدير مزوده فقط حسب العضوية والصلاحية.
- جميع عمليات الأعمال تمر عبر RPCs من نوع `SECURITY DEFINER` مع `search_path` ثابت.
- الكتابة المباشرة إلى جداول الأعمال مسحوبة من `authenticated`.
- الحجز المتداخل ممنوع بقيد `EXCLUDE`، مع مفتاح idempotency لمنع التكرار.
- أرقام قائمة الانتظار تُنشأ داخل قفل transaction advisory لمنع تكرار الرقم عند التزامن.
- سجل `appt_audit_log` يحفظ إجراءات الإنشاء والتعديل وتغيير الحالات والربط.

## مسار الفصل لاحقًا

عند قرار الفصل النهائي، تكون الخطوات الآمنة:

1. إيقاف عمليات الكتابة مؤقتًا على وحدة المواعيد.
2. تصدير جميع كائنات وبيانات `appt_*` فقط.
3. إنشاء قاعدة المواعيد الجديدة وتطبيق migrations نفسها.
4. استبدال `auth.uid()` بمعرف الهوية الموحد القادم من SSO عند الحاجة.
5. تحديث `VITE_KAHEEL_MARKET_URL` وعقد الربط الخارجي.
6. تشغيل اختبارات العزل والتزامن قبل إعادة فتح الكتابة.

لا يلزم في هذا المسار نسخ أي جدول أو كود من سوق كَحيل.
