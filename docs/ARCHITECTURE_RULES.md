# قواعد بنية كَحيل — KAHEEL Architecture Rules

هذه القواعد تمنع التوسّع العشوائي: كل جدول أو حاوية أو مسار جديد يجب أن يكون له مكان
معروف مسبقاً. القواعد مفروضة في ثلاث طبقات: قاعدة البيانات، التخزين، والمستودع.

---

## 1) الجداول — البادئة `mkt_` إلزامية

كل جدول جديد في مخطط `public` يجب أن يبدأ بـ `mkt_`. إنشاء مخطط (schema) جديد ممنوع تماماً.

الجداول الأساسية المستثناة (موجودة مسبقاً، لا تُنشأ ولا تُعاد تسميتها):

```
profiles  tenants  tenant_memberships  tenant_invitations
user_roles  user_permissions  audit_log  login_attempts  rate_events
```

**الفرض:** `EVENT TRIGGER structure_guard` في PostgreSQL يعمل على `ddl_command_end`
ويرفض `CREATE TABLE` المخالف و`CREATE SCHEMA` برسالة تشرح القاعدة وبديل التسمية.

| ماذا يحدث | أين يُسجَّل |
| --- | --- |
| جدول جديد ملتزم | صف `allowed` في `public.mkt_structure_guard_events` |
| محاولة مرفوضة | تحذير `[STRUCTURE_GUARD] rejected ...` في سجلات قاعدة البيانات |
| توثيق محاولة مرفوضة | `select public.structure_guard_log_rejection('public.x', 'CREATE TABLE', 'السبب')` |

> الأمر المرفوض يُلغي معاملته بالكامل، فلا يمكن للحارس أن يكتب صفاً عن رفضه هو —
> لذلك الدليل الدائم لحظة الرفض هو تحذير سجلات قاعدة البيانات، والتوثيق في الجدول
> يُسجَّل بعدها عبر الدالة أعلاه (مسؤول المنصة أو أدوات الفحص).

## 2) حاويات التخزين — البادئة `mkt-` والقائمة المعتمدة

الحاويات المعتمدة حالياً: **`mkt-media`** (صور الإعلانات والمتاجر) و**`mkt-chat`**
(مرفقات المحادثات). أي حاوية جديدة يجب أن تبدأ بـ `mkt-` وتُضاف إلى القائمة في
`scripts/check-structure.mjs` مع سياسات RLS على `storage.objects` في نفس التغيير.

الحاويات تُنشأ بأداة Storage فقط (لا `INSERT INTO storage.buckets`)، لذلك الفرض هنا
في المستودع: `npm run guard:structure` يفشل عند ظهور اسم حاوية غير معتمد في `src/`.

## 3) المسارات — الجذور المعتمدة فقط

| الجذر | الغرض |
| --- | --- |
| عام (بدون بادئة) | صفحات السوق المتاحة للجميع |
| `/my/*` | منطقة الحساب الشخصي للمستخدم المسجّل |
| `/business/*` | بوابة المنشأة (المتجر، الفريق، التحقق) |
| `/admin/*` | كونسول مسؤول المنصة |
| `/api/*` | مسارات خادمية؛ `/api/public/*` للنداءات الخارجية |
| `/guides/*`, `/profiles/*` | الأدلة والصفحات الشخصية العامة |

كل مسار جديد يُسجَّل في `src/lib/routes-map.ts`، وكل مسار قديم يُنقل بقاعدة 301 لا بحذف.
لا تُنشأ جذور جديدة (مثل `/dashboard` أو `/app`) دون تحديث هذا الجدول أولاً.

## 4) الفحص الآلي

```bash
npm run guard:structure
```

يفحص `src/`: أسماء الجداول في `.from("...")`، أسماء الحاويات، وجذور المسارات في
`src/routes/`. يمكن تشغيله يدوياً أو ضمن البناء/CI.

## 5) طلب استثناء (لصاحب المشروع فقط)

الاستثناء مؤقت ومحدود بمدة، ولا يُمنح إلا لحاجة مشروعة موثّقة:

```sql
-- 1) تعطيل مؤقت (السبب إلزامي، والمدة بالدقائق بحد أقصى 240)
select public.structure_guard_disable('ترحيل جدول تكاملات خارجي مطلوب لمزود الدفع', 30);

-- 2) نفّذ التغيير المطلوب فوراً

-- 3) إعادة التفعيل مباشرة بعد الانتهاء — لا تتركه معطلاً
select public.structure_guard_enable();
```

- الدالتان متاحتان لمسؤول المنصة فقط (`mkt_platform_admins`)، وكل تعطيل/تفعيل يُسجَّل
  في `mkt_structure_guard_events`.
- التعطيل ينتهي تلقائياً بانتهاء المدة حتى لو نُسي `structure_guard_enable()`.
- في المقابل، الاستثناء في المستودع يعني تحديث القائمة في `scripts/check-structure.mjs`
  وتوثيق السبب في هذا الملف — لا تعطيل السكربت.
