# إلغاء واجهة الحساب الشخصي القديمة (`/me`) — 03/08/2026

الهدف: إزالة الشكل القديم نهائيًا مع الإبقاء الكامل على البيانات والجداول
والدوال الخلفية، وتوجيه الجميع إلى النسخة الجديدة المعتمدة.

## 1) ما أُزيل
- `src/routes/_authenticated/me.tsx` (لوحة «حسابي الشخصي» القديمة: طلباتي،
  مشاريعي، مستنداتي، الدعوات، التنبيهات، عهدتي، الإعدادات الشخصية) — حُذف
  الملف بالكامل مع جميع استعلاماته وبطاقاته وSkeleton الخاص به.
- `personalGroups` في `src/components/AppLayout.tsx`: القائمة الجانبية القديمة
  للحساب الشخصي (7 عناصر + الإعدادات الشخصية) وفرعها في `NavLinks`، ومعها
  الأيقونتان `FileText` و`MailOpen` اللتان لم تبق لهما استخدام.
- `COMPANY_ONLY_PATHS` والتحويل القديم `navigate({ to: "/me" })` من داخل
  `AppLayout`.
- مدخل `rule("/me", "authenticated", "app")` من `src/lib/routes-map.ts`.

لم يُحذف أي جدول أو دالة أو سياسة أو صف؛ لا تغييرات في قاعدة البيانات إطلاقًا.

## 2) التحويلات الجديدة
- `src/routes/me.tsx` (جديد، `ssr: false`, `beforeLoad` فقط، بلا واجهة): مُحوِّل
  مركزي يقرأ الدور من الخادم ثم يحوّل مرة واحدة:
  - غير مسجّل ⇒ `/auth`
  - مدير منصة غير مقيّد ⇒ `/admin`
  - حساب منشأة نشط ⇒ `/dashboard/business`
  - حساب شخصي نشط ⇒ `/dashboard/profile`
  - لا حساب مُختار ⇒ `/choose-account?next=/dashboard/profile`
- `accountHome()` في `src/hooks/use-accounts.ts`: الحساب الشخصي/الفردي أصبح
  `/dashboard/profile` بدل `/me`.
- `AppLayout`: أي حساب شخصي داخل صدفة العمليات يُحوَّل إلى `/dashboard/profile`
  (`PERSONAL_HOME`)، فلم تبق للحساب الشخصي أي صفحة في الصدفة القديمة.
- `routes-map.ts`: `/me` مسجّل الآن كـ `legacy` مع `legacy_redirect:
  "/dashboard/profile"` (الوجهة الديناميكية يتولاها ملف المسار نفسه).

## 3) نتيجة فتح `/me` فعليًا (Playwright، جلسات حقيقية)
| الحالة | النتيجة |
| --- | --- |
| غير مسجّل | `/auth` |
| مدير النظام `o11339911@gmail.com` | `/admin` (وكذلك بعد Reload) |
| حساب شخصي (`qa-individual…`) | `/choose-account` ⇒ بعد الاختيار `/dashboard/profile` ⇒ حماية النسخة الجديدة نقلته إلى `/market-setup` |
| حساب منشأة (`qa-contractor…` / مؤسسة مقاول الاختبار) | `/dashboard/business` ⇒ حماية الصفحة الجديدة نفسها نقلته إلى `/market-setup` (تأكيد: فتح `/dashboard/business` مباشرة يعطي النتيجة ذاتها، فالتحويل ليس من `/me`) |
| Reload على `/me` | نفس الوجهة، بلا وميض للواجهة القديمة |
| زر الرجوع | يعود إلى الصفحة السابقة (`/`) ولا يُعيد فتح الشكل القديم (`replace: true`) |
| تسجيل خروج ثم دخول | التوجيه المركزي في `/auth` كما هو: مدير ⇒ `/admin`، غيره ⇒ منتقي الحساب |

- لا يوجد أي `href="/me"` أو `navigate('/me')` باقٍ في الشيفرة (بحث شامل:
  `routes`، `routes-map.ts`، الهيدر، قائمة الحساب، الشريط السفلي، صفحات
  الدخول، روابط الإشعارات) — النتيجة صفر.
- لا 404: المسار ما زال مسجّلًا ويُحوِّل مركزيًا.

## 4) المقاسات والأخطاء
- 320 / 390 / 768 / 1024 / 1366 / 1440: صفر Overflow في كل الحالات المختبَرة.
- صفر أخطاء Console في مسار مدير النظام والحساب الشخصي والمنشأة.
  (ظهر في تشغيل واحد تحذير React قديم عن `setState` في مكوّن غير مُركَّب على
  `/market-setup`، غير مرتبط بهذه الدفعة ولم يتكرر.)
- نسخة الإدارة والسوق لم تتغيّرا: لا تعديل على `AdminShell` أو `MarketShell`
  أو `DashboardShell`.

## 5) البناء
- `tsgo --noEmit`: نظيف.
- `vite build` (`npm run build`): نجح.

## 6) مكوّنات قديمة بقيت — والسبب
- `AppLayout` وصفحات العمليات (`/requests`, `/projects`, `/my-documents`,
  `/invitations`, `/notifications`, `/settings`, `/my-custody`): تبقى لأنها
  وظائف الكيان الداخلي (ERP) وليست الواجهة الشخصية القديمة؛ لم تصبح لها الآن
  نسخة ثانية: الحساب الشخصي لا يفتحها إطلاقًا.
- `useMyInvitations` في `/invitations`: ما زال مستخدمًا داخل صفحة الدعوات
  الإدارية (صلاحية `users.manage`).
- مفاتيح الترجمة `me.*` في `ar.json` / `en.json`: تُركت دون حذف لأنها بيانات
  نصية غير مرتبطة بمسار، وحذفها لا يضيف قيمة تشغيلية.
