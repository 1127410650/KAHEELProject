# تدقيق: إغلاق الدفعة الأولى — قاعدة الأنشطة المرجعية (03/08/2026)

## النطاق المنفَّذ
1. **صفحة الإدارة `/admin/activities`** — 3 تبويبات: شجرة الأنشطة (إنشاء قطاع/نشاط، تعطيل، دمج)، الاقتراحات (قبول/رفض/دمج)، تقرير الترحيل.
2. **واجهة اختيار النشاط (`ActivityPicker`)** — مدمجة في:
   - إنشاء منشأة: `src/components/marketplace/BusinessQuickCreate.tsx` (استبدلت الحقول النصية الحرة).
   - تعديل المنشأة: `src/routes/dashboard/business.tsx` (تُحمَّل الروابط الحالية، ولا يُعدَّل شيء إلا بعد الحفظ).
3. **تقرير الترحيل** — قراءة وتحليل فقط عبر `mkt_activity_migration_report`؛ لا تعديل تلقائي على أي كيان.
4. **قطاعات مفتوحة** — دوال `mkt_admin_create_group` / `mkt_admin_create_activity` تتيح إضافة أي قطاع أو نشاط مشروع مستقبلًا دون تغيير الكود.
5. **قطاع الرياضة** — أُضيف مع: الأندية الرياضية، مراكز اللياقة، الأكاديميات الرياضية، الأندية النسائية، الملاعب، التدريب الرياضي، المدربين الشخصيين، تأجير المعدات الرياضية، وأنشطة فرعية إضافية ومرادفات بحث (جيم، فتنس، بادل، …).

## الضوابط المحققة
- لا اختيار تلقائي: الاختيار لا يحدث إلا بضغطة المستخدم على نتيجة، مهما كانت درجة الثقة.
- «النشاط غير موجود» → إدخال يدوي يُحفظ **اقتراحًا** بحالة `pending` فقط، ولا يظهر في القاعدة قبل مراجعة الإدارة.
- الأنشطة الفرعية مقيدة بالنشاط الرئيسي نفسه، ونشاط رئيسي واحد فقط.
- لا Publish، ولا عمل خارج هذه الدفعة.

## إصلاح ظهر أثناء الاختبار
كان بحث الأنشطة يفشل بـ 401 لغير المسجلين لأن سياسة القراءة العامة كانت تستدعي `mkt_is_platform_admin()` المسحوبة الصلاحية من `anon`.
الحل: فصل سياسة القراءة العامة (النشط فقط) عن سياسة قراءة المسؤول (`authenticated` فقط) على `mkt_activities` و`mkt_activity_groups` — دون منح `anon` أي دالة إدارية.

## نتائج الاختبار
- المقاسات 320 / 390 / 768 / 1024 / 1366 / 1440: `scrollWidth == innerWidth` في كل المقاسات، قبل الاختيار وبعده → **لا Overflow**.
- **Console Errors: 0** بعد الإصلاح (كانت 2×401 لكل مقاس قبله).
- البحث بالمرادفات يعمل: «جيم» → مراكز اللياقة البدنية، الأندية النسائية.
- `tsgo --noEmit`: نجح. `vite build`: نجح.
- نسخة الكمبيوتر ونسخة الجوال مستقلتان (الفروق عبر `sm:`/`lg:` فقط، لا تغيير سلوكي).

## قيود وملاحظات
- بيئة الفحص `signed_out`، لذلك اختُبرت واجهة الاختيار في صفحة QA مؤقتة (حُذفت بعد الاختبار)، ولم تُختبر بجلسة دخول: حفظ الاقتراح، ربط الأنشطة بالكيان، وشاشة `/admin/activities` تحتاج جلسة QA لاختبار سلوكي كامل.
- الحقول النصية القديمة (`main_activity`, `sub_activities`) لا تزال محفوظة للتوافق، وتُحدَّث من النشاط المرجعي المختار عند الحفظ فقط.

## 3) اختبار العزل ومحاولات التجاوز اليدوي (REST مباشر)
- مستخدم عادي: إنشاء/تعديل `mkt_activities` أو `mkt_activity_groups` → مرفوض (403/400).
- تعديل `official_code` أو اعتماد اقتراحه الخاص → مرفوض (`admin only`).

- محاولة صف رئيسي ثانٍ مباشرة → مرفوض بقيد التفرد؛ نشاط رئيسي واحد فقط دائمًا.
