# تحسين الصفحة الرئيسية ونموذج الإعلان وإدارة الحسابات

تنفيذ على ثلاث دفعات متتابعة. لا Publish. لا مساس بـ RLS القائم أو نظام البلاغات أو المفضلة أو قرار الفوتر أو الشريط السفلي أو فرض دولة الحساب.

## ما تم التحقق منه قبل التخطيط

- `mkt_categories` تحتوي 13 تصنيفًا جذريًا فقط، بلا أي تصنيف فرعي (`parent_id` فارغ في كل الصفوف). لذا الاختيار المتدرج يحتاج بناء شجرة حقيقية بمستويين إضافيين.
- `mkt_listings` لا تحتوي: `latitude`, `longitude`, `location_accuracy`, `location_source`, `district`, `address_text`, ولا خاصية عرض تقريبي/دقيق.
- `mkt_listing_images` لا تحتوي حقل نوع صورة (عادية / 360°).
- لا يوجد جدول نشاط سوق، ولا مكتبة خرائط أو مزوّد ترميز جغرافي في المشروع.
- `mkt_listing_types`: service, product, equipment_sale, equipment_rent, need_supplier, need_contractor.

## الدفعة الأولى — الرئيسية والاقتراحات والحسابات

1. الهيرو: العنوان الجديد «اكتب كل ما تحتاجه هنا: عقار، خدمات، موردون، معدات ومواد بناء»، نص البحث الجديد، حذف سطر «تصفح مجانًا…» دون بديل، وتقليص ارتفاع القسم على الجوال.
2. حذف شبكة التصنيفات الكبيرة من الرئيسية فقط (تبقى في البحث والفلاتر والنموذج وصفحة `/categories/$slug`)، والإبقاء على صف المجالات المختصر: عقارات / خدمات / منتجات / معدات / منشآت.
3. حذف قسم «منشآت مقترحة» واستبداله بـ «إعلانات مقترحة لك».
4. ترتيب الرئيسية: هيدر ← عنوان ← بحث ← «أضف إعلانًا» ← صف المجالات ← مقترحة لك ← أحدث الإعلانات ← قريبة منك (عند إذن الموقع) ← الفوتر. لا أقسام فارغة.
5. البطاقات: صورة الغلاف، العنوان، السعر والعملة، المدينة، النوع/التصنيف الفرعي، الوقت، المفضلة، ومؤشر «360°» عند وجود بانوراما. لا علامة توثيق على بطاقة الإعلان.
6. حذف شريط التبويبات من `DashboardShell` نهائيًا، ونقل كل العناصر إلى قائمة الحساب الموحدة وصفحة الإعدادات.
7. إعادة تنظيم `AccountMenu`: الهوية الحالية ← التبديل بين الحسابات ← «+ إضافة منشأة» ← نشاطي (إعلاناتي، طلبات عروض السعر، المحادثات، التنبيهات مع عدد غير المقروء، المفضلة، بلاغاتي، مخالفاتي) ← الإدارة (الحساب الشخصي، ملف المنشأة عند وجودها، الإعدادات) ← تسجيل الخروج. Bottom Sheet واحد على الجوال.
8. الإعدادات: أقسام الحساب الشخصي، ملف المنشأة (أو «إضافة منشأة» عند عدم وجودها)، التواصل والخصوصية، الإشعارات (رسائل، طلبات، إعلانات، مراجعة إعلان، بلاغات ومخالفات، بريد، تطبيق)، اللغة، الأمان، الدولة والمدينة — كصفحة تجميعية للأقسام القائمة بدون تكرار.
9. جدول النشاط `mkt_user_activity` (migration): `user_id`, `event_type` (search / view_ad / favorite / open_category)، `ad_id`, `category_id`, `search_query`, `city_id`, `created_at`؛ RLS: كل مستخدم يكتب ويقرأ نشاطه فقط؛ GRANT للـ authenticated و service_role فقط؛ تطبيع نص البحث وتقصيره؛ حذف تلقائي لما يتجاوز 90 يومًا؛ الكتابة غير حاجبة ولا يوقف فشلها البحث أو فتح الإعلان.
10. الخصوصية: مفتاح «استخدام نشاطي لتحسين الاقتراحات» مفعّل افتراضيًا مع زر «مسح سجل النشاط».
11. محرك الاقتراحات (بلا أي API ذكاء اصطناعي): ترتيب حسب التصنيفات الأكثر مشاهدة، آخر عمليات البحث، مشابهة المفضلة، مدينة الحساب، ثم الحداثة؛ استبعاد إعلانات المستخدم نفسه ومنع التكرار داخل القسم؛ للزائر أو عند تعطيل التخصيص: Local Storage للجلسة ثم أحدث إعلانات المدينة فالدولة.

## الدفعة الثانية — نموذج الإعلان

1. «عنوان العرض» إلزامي يدويًا في حقل `title` الحالي: 5–120 حرفًا، تشذيب المسافات، رفض الفراغ أو الرموز فقط، ولا توليد تلقائي من التصنيف.
2. التصنيف متعدد المراحل: مجال ← قسم ← نوع فرعي ← خصائص. migration لبناء شجرة `parent_id` من الجذور القائمة (عقار: شقق/فلل/أراضٍ/عمائر/مكاتب/محلات/مستودعات/مزارع/استراحات/غرف/استثماري؛ معدات: ثقيلة/خفيفة/صناعية ← حفارات/رافعات/مولدات/ضواغط؛ مواد بناء: حديد/أسمنت/بلوك/عزل/كهرباء/سباكة/تشطيبات؛ خدمات: مقاولات/صيانة/نقل/هندسة/تصميم/تشغيل) دون تكرار الموجود.
3. مرحلة العرض (بيع / إيجار / مطلوب شراء / مطلوب استئجار) تُشتق من `type_code` القائم، وخصائص العقار والمعدات تُخزَّن في `specs` مع إظهار الحقول المناسبة فقط.
4. واجهة الاختيار: مسار «عقار ← شقق ← للإيجار»، زر رجوع، بحث داخل القوائم الطويلة، Bottom Sheet على الجوال.
5. الموقع: أعمدة جديدة على `mkt_listings` (`latitude`, `longitude`, `location_accuracy`, `location_source`, `district`, `address_text`, `location_precision`) + Leaflet/OpenStreetMap وترميز عكسي عبر Nominatim مع تحديد المدينة من `mkt_cities`.
6. سلوك الإذن: جلب تلقائي عند إذن ممنوح مسبقًا؛ زر «استخدام موقعي الحالي» مع توضيح أن الموقع لا يُحفظ إلا بعد المراجعة والإرسال؛ عند الرفض: مدينة الحساب كقيمة أولية وإدخال يدوي كامل. كل الحقول قابلة للتعديل وتحريك العلامة متاح، ولا يُعدَّل موقع الحساب ولا موقع المنشأة، والدولة تُفرض خادميًا بلا Dropdown، والإحداثيات الدقيقة غير معروضة للعامة (تقريبي افتراضيًا).
7. «النشر باسم»: الحساب الشخصي + المنشآت المصرّح بها + «+ إضافة منشأة» الذي يحفظ مسودة الإعلان والصور، يفتح نموذج منشأة مختصرًا بدون إنشاء حساب دخول جديد، ثم يعود ويختار المنشأة الجديدة تلقائيًا. لا شرط توثيق للنشر.

## الدفعة الثالثة — الصور و360° والاختبارات

1. إزالة حد «حتى 8 صور» وأي حد عددي ظاهر، مع حماية بحد حجم لكل ملف، حد مساحة للحساب، Rate Limit، فحص نوع الملف وبايتاته، ضغط ونسخ مصغّرة.
2. اختيار متعدد، دفعات لاحقة، ترتيب بالسحب، اختيار الغلاف، حذف/استبدال، شريط تقدم لكل صورة، إعادة محاولة الفاشل، وحفظ المسودة دون فقد الصور.
3. حقل نوع الصورة على `mkt_listing_images` (عادية / 360°) واختيار النوع عند الرفع، مع فحص نسبة قريبة من 2:1 للـ Equirectangular، ورسالة مواصفات وحفظها كصورة عادية عند عدم المطابقة.
4. عارض 360° خفيف مفتوح المصدر يُحمَّل فقط عند وجود صورة بانوراما: سحب، لمس، ملء الشاشة، وحركة الهاتف اختيارية بعد الإذن. الصور العادية في المعرض المعتاد.
5. تنفيذ الاختبارات الـ46 (Playwright على 320/390/1366، عربي RTL وإنجليزي LTR، overflow = 0، لا أخطاء Console حاجبة) مع `tsgo --noEmit` و`vite build` وفحص أمني، ثم التقرير `.lovable/audit/2026-08-02-home-ads-location-categories-360.md`.

## ملاحظات تقنية

- تعديلات قاعدة البيانات المطلوبة والمثبتة الحاجة: `mkt_user_activity`، أعمدة الموقع على `mkt_listings`، نوع الصورة على `mkt_listing_images`، مفتاح تخصيص الاقتراحات على ملف المستخدم، وشجرة التصنيفات. لا تغيير على سياسات RLS القائمة.
- Nominatim يُستدعى بمعدّل منخفض ومع الإسناد المطلوب، ويظل الإدخال اليدوي كافيًا عند فشله.
- Leaflet وعارض 360° يُحمَّلان ديناميكيًا بعد الترطيب فقط حتى لا يتأثر SSR أو حجم الحزمة الأولى.
