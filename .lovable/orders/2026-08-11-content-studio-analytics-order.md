أريد تنفيذ مرحلة جديدة مستقلة باسم **«استوديو المحتوى والتحليلات لمنصة كحيل»**، تكون مكملة مباشرة لمرحلة **«مركز قيادة مدير المنصة العام»** السابقة.

هذه المرحلة لا تعيد إنشاء لوحة المدير، ولا الشريط الجانبي، ولا نظام الحسابات والأدوار والصلاحيات، ولا سجل العمليات، ولا السوق أو المشاريع. المطلوب توسيع مركز القيادة الحالي بوحدتين مترابطتين:

1. **استوديو محتوى بصري** يمكّن مدير المنصة من التعامل مع الرئيسية والصفحات وكأنها لوحة رسم منظمة: إضافة الأقسام، ترتيبها، تغيير شكلها، التحكم في الأزرار والتبويبات والقوائم، إنشاء صفحات جديدة، إيقاف أو جدولة الصفحات، وإدارة الحملات وربطها بإعلان أو منتج أو متجر أو تصنيف أو صفحة داخلية.
2. **محرك تتبع وتحليلات موحد** يقيس أداء الصفحات والأقسام والحملات والإعلانات والمتاجر والمنتجات، ويعرض نتائج شاملة لمدير المنصة ونتائج معزولة لصاحب المتجر أو الإعلان حسب هويته النشطة وصلاحياته.

الهدف هو بناء نظام متكامل حقيقي، لا واجهة شكلية ولا أرقام تجريبية. يجب أن تكون كل وظيفة مرئية مرتبطة ببيانات وصلاحيات وإجراء فعلي.

## 1. العلاقة الملزمة مع المرحلة السابقة

1. استخدم المسار والهيكل العام والصلاحيات وسجل العمليات وصندوق العمل الموجود في «مركز قيادة مدير المنصة العام».
2. أضف وحدات المحتوى والتحليلات إلى الشريط الجانبي السابق، ولا تنشئ لوحة مدير ثانية.
3. تظهر طلبات اعتماد المحتوى، أخطاء النشر، الحملات المنتهية، مشكلات الروابط، وفشل استقبال أحداث التتبع داخل «صندوق العمل» و«الصحة التشغيلية» في مركز القيادة السابق.
4. استخدم نفس مدير المنصة وموظفي المنصة ونفس نظام الصلاحيات التفصيلي. لا تنشئ نوع مستخدم أو حساب Auth مستقل لإدارة المحتوى.
5. استخدم سجل العمليات السابق لكل إنشاء أو تعديل أو اعتماد أو نشر أو إيقاف أو استرجاع نسخة أو تصدير تقرير.
6. الحساب الشخصي والمنشآت والكيانات تبقى منفصلة، والهوية النشطة تبقى المصدر النهائي لبيانات صاحب المتجر أو الإعلان.
7. استخدم نفس `tenant_id` و`owner_user_id` وعلاقات الملكية والعضوية القائمة بعد التحقق من أسمائها الفعلية. لا تنسخ متجرًا أو إعلانًا أو منتجًا أو حسابًا من أجل التحليلات.
8. لا تغيّر قرارات التوثيق؛ التوثيق شارة بصرية فقط ولا يمنح ترتيبًا أو وصولًا أو تحليلات إضافية.
9. لا تغيّر قواعد الدول والأسواق أو RLS أو مسارات السوق العامة إلا بالقدر اللازم لعرض المحتوى المنشور وتسجيل الحدث الآمن.
10. لا تنفذ Publish للمنصة في نهاية هذه المرحلة.

## 2. قواعد التنفيذ والحذر

1. ابدأ بجرد كامل لما هو موجود فعليًا: صفحات الإدارة، الصفحة الرئيسية، الهيدر، الفوتر، شريط الجوال، التبويبات، مكونات العرض، الإعلانات، المتاجر، المنتجات، الحملات إن وجدت، جداول التحليلات إن وجدت، Routes، RLS، RPC، Edge Functions، Storage، الأدوار والصلاحيات، وتقارير `.lovable/audit/`.
2. لا تفترض أن كل الوحدات المذكورة منفذة. اربط الوحدة الموجودة فعليًا، واجعل التكامل مع الوحدة المستقبلية خلف Feature Flag واضحًا.
3. لا تنشئ جدولًا أو مكونًا أو SDK تتبع ثانيًا إذا وجد ما يؤدي الغرض. وحّد الموجود ونظفه بهدوء.
4. لا تنفذ ترحيلًا جماعيًا واسعًا. أنشئ كل تغيير في دفعة محدودة، واختبره أمنيًا ووظيفيًا قبل الانتقال.
5. لا تحذف محتوى منشورًا أو صفحات أو نسخًا سابقة نهائيًا. استخدم إلغاء النشر، التعطيل، الأرشفة، الاستبدال أو إعادة التوجيه.
6. لا تسمح بإدخال HTML أو CSS أو JavaScript عشوائي من لوحة التحكم. المحرر يستخدم مكتبة مكونات آمنة ومعتمدة فقط.
7. لا تستخدم `service_role` أو Secret key في المتصفح. لا تمنح العميل وصولًا مباشرًا إلى جدول الأحداث الخام.
8. فعّل RLS على كل جدول في Schema مكشوف، وافصل بين منح الوصول للـData API وبين سياسات الصفوف.
9. لا تستخدم `user_metadata` لاتخاذ قرار صلاحية. استخدم مصدر الصلاحيات الحالي الموثوق أو `app_metadata` عند الحاجة، مع مراعاة أن JWT قد لا يتحدث فورًا بعد تغيير الدور.
10. راجع Changelog ووثائق Supabase الحالية قبل التنفيذ، ثم افحص Advisors بعد كل دفعة تمس قاعدة البيانات أو RLS.
11. لا تدخل بيانات حقيقية، ولا ترسل إشعارات فعلية، ولا تشغل حملات حقيقية أثناء الاختبار. استخدم Test Mode واضحًا ونظف بياناته بعد الاختبارات.

## 3. النتيجة المعمارية المطلوبة

ابنِ النظام كأربع طبقات مترابطة:

### الطبقة الأولى — Design System

رموز تصميم مركزية وآمنة: الألوان، الخطوط، أحجام النص، الحواف، الظلال، المسافات، عرض الحاوية، وأشكال الأزرار. يتم تعديلها ضمن حدود معتمدة مع معاينة كاملة، ولا تسمح بقيم تؤدي إلى كسر الجوال أو ضعف القراءة.

### الطبقة الثانية — Content Studio

محرر مرئي للصفحات والأسطح المشتركة، يعتمد على Sections وBlocks ذات أنواع معروفة، مع سحب وترتيب ونسخ وإخفاء واسترجاع وإعدادات متجاوبة.

### الطبقة الثالثة — Publication & Campaigns

مسودات، مراجعة، اعتماد، نشر فوري أو مجدول، إلغاء نشر، نسخ غير قابلة للتعديل بعد النشر، رجوع لنسخة سابقة، حملات ومواضع وربط بأهداف المنصة.

### الطبقة الرابعة — Analytics

كتالوج أحداث موحد، استقبال آمن للأحداث، تجميع يومي/ساعي، تحليلات مدير المنصة، تحليلات مالك الهوية، وطبقة توضيح تعريف كل رقم ومن أين أتى.

## 4. المسارات داخل مركز القيادة

استخدم المسار الإداري السابق ووسّعه. أسماء مقترحة فقط، ويجب مطابقتها مع بنية المشروع الفعلية ومنع التكرار:

- `/platform-admin/content`
- `/platform-admin/content/pages`
- `/platform-admin/content/navigation`
- `/platform-admin/content/components`
- `/platform-admin/content/campaigns`
- `/platform-admin/content/media`
- `/platform-admin/content/revisions`
- `/platform-admin/analytics`
- `/platform-admin/analytics/content`
- `/platform-admin/analytics/campaigns`
- `/platform-admin/analytics/marketplace`
- `/platform-admin/analytics/quality`

أضف لصاحب الحساب أو المنشأة المصرح له شاشة «الإحصاءات» داخل سياق هويته النشطة الحالية. لا تنشئ حسابًا أو Dashboard منفصلًا. إذا كانت البنية الحالية تعتمد مسار الحساب أو المنشأة، ضع الإحصاءات داخله واستخدم مبدّل الحساب الحالي.

## 5. الصلاحيات المطلوبة

أعد استخدام نظام الصلاحيات السابق، وأضف أقل عدد لازم من الصلاحيات التفصيلية بعد الجرد. أمثلة وظيفية يجب مواءمتها مع الأسماء الحالية:

- عرض استوديو المحتوى.
- إنشاء وتعديل المسودات.
- إدارة التصميم العام.
- إدارة الهيدر والفوتر والتنقل.
- إنشاء صفحات وتعديل خصائصها.
- إرسال المحتوى للمراجعة.
- اعتماد المحتوى.
- النشر والإلغاء والجدولة.
- استعادة نسخة سابقة.
- إدارة الحملات والمواضع.
- إدارة مكتبة الوسائط.
- عرض تحليلات المنصة.
- تصدير تحليلات المنصة.
- عرض جودة البيانات.
- عرض تحليلات الهوية/المتجر/الإعلان.

افصل بين **المصمم/المحرر** و**المعتمد/الناشر**. لا يستطيع من يملك صلاحية تعديل المسودة نشرها تلقائيًا ما لم يملك صلاحية النشر أيضًا. النشر والإلغاء واستعادة نسخة تحتاج تأكيدًا وسببًا وسجلًا.

صاحب المتجر أو الإعلان لا يحصل على صلاحيات محتوى المنصة. يحصل فقط على تحليلات العناصر التي تملكها هويته النشطة، وبشرط عضوية فعالة وصلاحية مثل `analytics.view` داخل الكيان.

## 6. واجهة استوديو المحتوى المرئي

أريد تجربة تشبه «ورقة وأنا أرسم عليها»، لكن مبنية بطريقة متجاوبة وآمنة، وليست عناصر بإحداثيات ثابتة تكسر الجوال.

### شريط الأدوات العلوي

يحتوي على:

- اختيار السطح أو الصفحة.
- حالة النسخة: مسودة، قيد المراجعة، معتمدة، مجدولة، منشورة، ملغاة، مؤرشفة.
- اختيار لغة المعاينة: العربية/الإنجليزية.
- اختيار المقاس: جوال صغير، جوال، تابلت، كمبيوتر، عرض مخصص.
- تراجع وإعادة.
- حفظ المسودة.
- معاينة في تبويب آمن.
- إرسال للمراجعة.
- نشر الآن أو جدولة.
- سجل النسخ.

### العمود الأيسر — مكتبة المكونات

اعرض المكونات حسب مجموعات قابلة للبحث والسحب:

- التخطيط.
- النصوص والوسائط.
- السوق والإعلانات.
- المتاجر والمنتجات.
- الحملات.
- التنقل والتبويبات.
- النماذج والإجراءات.
- المحتوى المعلوماتي.

### الوسط — لوحة الرسم

- عرض الصفحة الحقيقية داخل إطار المقاس المختار.
- سحب المكونات وإعادة ترتيبها.
- تحديد المكون بالنقر.
- حدود خفيفة ومقابض واضحة.
- نسخ، نقل، قفل، إخفاء، حذف من المسودة، أو تحويل إلى مكون قابل لإعادة الاستخدام.
- عرض Grid ومسافات ومحاذاة.
- Layers صغيرة لمعرفة ترتيب الأقسام والعناصر.
- منع تداخل العناصر أو خروجها من الحاوية.
- لا تستخدم Absolute positioning للمحتوى الأساسي.

### العمود الأيمن — خصائص العنصر

يعرض حسب النوع:

- المحتوى والنصوص والترجمة.
- الصورة/الفيديو والنص البديل.
- العرض والمحاذاة والمسافة والخلفية.
- قواعد الظهور حسب المقاس.
- الرابط أو الإجراء عند الضغط.
- مصدر البيانات الديناميكي.
- الدولة أو الجمهور أو التاريخ.
- إعداد التتبع واسم الهدف المقروء.
- إعدادات Accessibility.

### خصائص المحرر

- Autosave للمسودة فقط.
- Undo/Redo لعدد كافٍ من الخطوات داخل الجلسة.
- اختصارات لوحة المفاتيح الأساسية.
- نسخ/لصق المكون داخل الصفحة أو بين مسودتين متوافقتين.
- تحذير عند مغادرة تغييرات غير محفوظة.
- Version guard يمنع موظفين من الكتابة فوق بعضهما بصمت.
- عند التعارض، اعرض مقارنة وخيار دمج آمن أو إنشاء نسخة جديدة؛ لا تستخدم Last write wins بصمت.

## 7. مكتبة المكونات الآمنة

أنشئ Component Registry في الكود أو البنية الحالية، بحيث يكون كل نوع مكون معروفًا وله Schema تحقق وإصدار. لا تسمح بأنواع غير مسجلة داخل نسخة منشورة.

المكونات الأساسية المطلوبة:

- Hero بصورة أو فيديو خفيف وعنوان وزر.
- عنوان، فقرة، Rich Text منظف، صورة، فيديو، Divider، Spacer.
- زر واحد أو مجموعة أزرار.
- شبكة تصنيفات.
- شريط تصنيفات أفقي قابل للسحب.
- شبكة إعلانات يدوية أو ديناميكية.
- أحدث الإعلانات.
- إعلانات مختارة يدويًا.
- عروض/حملات مميزة.
- شريط القصص الترويجية المدفوعة عند تنفيذ الوحدة فعليًا.
- شبكة متاجر أو منشآت.
- شبكة منتجات، فقط عند تفعيل وحدة التجارة في السوق المؤهل.
- فرص أو طلبات عروض أسعار، إذا كانت الوحدة منفذة.
- Tabs.
- Accordion/FAQ.
- Carousel بعدد شرائح محدود وضوابط وصول.
- تنبيه عام أو شريط صيانة.
- قسم نص وصورة.
- بطاقات مزايا.
- نموذج CTA آمن يفتح إجراء موجودًا، ولا ينشئ Form حرًا يرسل بيانات مجهولة.
- Footer section ضمن محرر الفوتر.

لكل Block معرّف ثابت `block_id` لا يتغير عند تعديل النص أو الشكل، حتى يمكن مقارنة أداء المكون بين النسخ. عند نسخ المكون، أنشئ `block_id` جديدًا لمنع دمج التحليلات.

## 8. التحكم في التصميم العام

أنشئ شاشة «هوية العرض» أو استخدم الشاشة القائمة إن وجدت. تسمح بتعديل آمن لـ:

- الألوان الأساسية والثانوية والحالات.
- الخط العربي والإنجليزي من قائمة معتمدة.
- أحجام النصوص ضمن Scale متناسق.
- شكل الأزرار والحقول والبطاقات.
- الحواف والظلال.
- المسافات القياسية.
- عرض الحاوية ونقاط التحول Breakpoints.
- الخلفية العامة.

أي تعديل على الهوية يمر كنسخة Draft ويظهر في Preview قبل النشر. لا تسمح بحقن CSS. نفذ فحص Contrast وإمكانية القراءة قبل النشر، واعرض الصفحات المشتركة المتأثرة.

## 9. إدارة الصفحات

أنشئ مدير صفحات يتيح:

- إنشاء صفحة فارغة.
- إنشاء من Template معتمد.
- نسخ صفحة موجودة إلى مسودة جديدة.
- إنشاء Landing Page لحملة.
- تعديل العنوان والمسار والوصف والترجمة والصورة الاجتماعية.
- ترتيب الصفحة داخل القوائم إذا كانت مرتبطة بالتنقل.
- نشر فوري أو مجدول.
- تحديد تاريخ إيقاف تلقائي.
- إلغاء نشر يدوي.
- أرشفة.
- استعادة نسخة سابقة.

### حالات الصفحة

استخدم حالات واضحة وقابلة للتدقيق:

- Draft.
- In review.
- Approved.
- Scheduled.
- Published.
- Unpublished.
- Archived.

### إنشاء المسار وإغلاقه

- تحقق من أن Slug غير محجوز وغير مكرر في اللغة والنطاق نفسيهما.
- امنع التعارض مع Routes الأساسية مثل الدخول والحساب والبحث والإدارة وAPI.
- لا تسمح بإغلاق صفحات الأمان أو الشروط أو تسجيل الدخول الحرجة دون صلاحية عليا وخطة بديلة.
- عند تغيير مسار صفحة منشورة، أنشئ Redirect مضبوطًا مع منع الحلقات.
- عند إلغاء نشر صفحة، اختر سلوكًا واضحًا: صفحة بديلة، الرئيسية، أو 404 محترفة.
- لا تحذف النسخة المنشورة أو تاريخها.
- يجب أن يتحدث Sitemap وCanonical وMeta حسب حالة الصفحة، إن كان المشروع يدعمها.

## 10. إدارة الهيدر والفوتر والقوائم والتبويبات

أنشئ محررًا بصريًا منفصلًا للأسطح المشتركة:

- Header الكمبيوتر.
- Header الجوال.
- Bottom navigation.
- Footer.
- قائمة الحساب.
- قوائم فرعية وتبويبات صفحات محددة.

يدعم:

- إضافة عنصر أو فاصل أو مجموعة.
- تغيير الترتيب بالمسحوب.
- اختيار الأيقونة والنص والترجمة.
- ربط بمسار داخلي أو إجراء معتمد.
- إظهار/إخفاء حسب حالة الدخول أو نوع الهوية أو الصلاحية أو الدولة أو Feature Flag.
- معاينة الجوال والكمبيوتر في اللحظة نفسها.

احمِ العناصر الحرجة. لا تسمح بإزالة وسيلة الوصول للحساب أو تسجيل الخروج أو العودة أو التنقل الأساسي بطريقة تحبس المستخدم. Bottom navigation في الجوال يبقى محدودًا وواضحًا ولا يتحول إلى صف مزدحم.

## 11. محرر الأزرار والإجراءات

كل زر أو بطاقة أو Banner يمكن ربطه بأحد الأهداف المعتمدة فقط:

- صفحة داخلية منشورة.
- تصنيف أو نتيجة بحث محددة.
- إعلان موجود ومنشور.
- منتج موجود ونشط.
- متجر/منشأة أو ملف معلن.
- فرصة أو طلب عرض سعر إذا كانت الوحدة موجودة.
- بدء طلب تواصل وفق الدورة الحالية.
- فتح خيارات الاتصال وفق إعدادات صاحب الحساب.
- إضافة إلى السلة عندما تكون التجارة مفعلة ومسموحة.
- رابط خارجي من نطاق مسموح بعد التحقق.
- تمرير إلى قسم داخل الصفحة.
- لا إجراء.

عند اختيار الهدف، استخدم Selector يبحث في السجلات المصرح بها ويعرض الاسم والمعرف والحالة والدولة وصاحب المحتوى. لا يقبل `target_id` مكتوبًا يدويًا بلا تحقق.

قواعد الربط:

- لا تنشر رابطًا إلى إعلان أو منتج أو متجر غير نشط أو غير مصرح بعرضه.
- يجب توافق الدولة والسوق بين الحملة والهدف، إلا إذا كانت الحملة متعددة الدول ومصرحًا بذلك.
- إذا أصبح الهدف موقوفًا أو مؤرشفًا بعد النشر، أوقف الرابط أو الحملة بأمان واعرض تنبيهًا في صندوق عمل المدير.
- لا تتجاوز إعدادات خصوصية رقم الجوال أو طلب التواصل.
- أضف Accessible label واضحًا لكل زر أيقوني.
- ينشأ `tracking_key` داخلي ثابت تلقائيًا، ولا يطلب من المحرر كتابة اسم حدث تقني.

## 12. المحتوى الديناميكي وربط البيانات

يستطيع المدير اختيار مصدر كل قائمة أو شبكة:

- اختيار يدوي لسجلات محددة.
- أحدث الإعلانات.
- إعلانات حسب التصنيف أو المدينة أو الدولة.
- متاجر حسب النشاط.
- منتجات حسب المتجر أو التصنيف، عند تفعيل التجارة.
- حملات أو عناصر مميزة سارية.
- محتوى مرتبط بسلوك الصفحة الحالي من دون إنشاء ملف شخصي حساس للزائر.

قواعد ملزمة:

- مصدر البيانات يستخدم الاستعلامات والمسارات الحالية ولا ينسخ السجلات داخل CMS.
- لا يظهر إلا المحتوى المنشور والمسموح في السوق النشط.
- RLS والخادم هما المصدر النهائي، وليس Filter الواجهة.
- التوثيق لا يغير ترتيب النتائج تلقائيًا.
- عند اختيار «الأكثر مشاهدة» أو «الأكثر تفاعلًا»، استخدم Aggregates موثوقة ومحمية من التلاعب وحركة المالك نفسه والزيارات الآلية.
- اعرض Preview بالبيانات المسموح بها فقط، ولا تفتح مسودة المحتوى أو بيانات سوق آخر.

## 13. الحملات والمواضع الإعلانية

أنشئ وحدة حملات داخل استوديو المحتوى، وميّز بوضوح بين:

- **إعلان مستخدم/متجر** موجود في السوق.
- **حملة ترويجية داخلية** يضعها مدير المنصة في موضع محدد.
- **ترويج مدفوع** لا يُعامل كمدفوع ولا يفعل الفوترة إلا إذا كانت وحدة الدفع والترويج منفذة فعليًا.

### بيانات الحملة

- الاسم الداخلي.
- الحالة.
- الهدف التجاري.
- المالك/الجهة الراعية عند الحاجة.
- الدولة أو الدول المسموحة.
- المدينة أو الجمهور العام عند الحاجة.
- تاريخ ووقت البدء والانتهاء.
- المنطقة الزمنية للعرض، مع التخزين في UTC.
- موضع العرض.
- Creative واحد أو عدة نسخ.
- ترتيب/وزن الظهور.
- Frequency cap عند الحاجة.
- رابط الهدف المعتمد.
- وسم «محتوى مروج» أو ما يلزم بصريًا.
- ميزانية أو قيمة مالية فقط عند وجود نظام مالي حقيقي؛ لا تعرض أرقامًا وهمية.

### مواضع مقترحة

- Hero الرئيسية.
- أسفل Hero.
- شريط القصص الترويجية.
- بين أقسام الرئيسية.
- أعلى صفحة تصنيف.
- داخل نتائج البحث في موضع معلن بوضوح.
- صفحة متجر أو إعلان إذا كانت السياسة تسمح.

### دورة الحملة

Draft → Review → Approved → Scheduled → Active → Paused/Ended → Archived.

لا يسمح بتعارض حملتين في موضع حصري دون تنبيه. اعرض Calendar زمني للمواضع، ومعاينة النتيجة حسب الدولة والمقاس واللغة. عند انتهاء الحملة تعود الصفحة تلقائيًا للبديل الآمن من دون فراغ أو كسر.

## 14. مكتبة الوسائط

أنشئ أو أعد استخدام مكتبة الوسائط العامة للمحتوى التسويقي فقط:

- صور، فيديوهات قصيرة، شعارات، أيقونات، وملفات عامة مسموحة.
- مجلدات ووسوم وبحث.
- اسم بديل ووصف وحقوق الاستخدام إن لزم.
- Crop وFocal point ونسخ متجاوبة.
- معرفة أين يُستخدم الأصل قبل الأرشفة.
- منع حذف أصل مستخدم في نسخة منشورة.
- فحص MIME والحجم والامتداد.

ممنوع خلط هذه المكتبة مع مستندات الهوية، السجلات التجارية، مرفقات المشاريع، الفواتير أو أي Bucket خاص. لا تجعل مستندًا خاصًا متاحًا في محرر المحتوى أو URL عام.

## 15. دورة المراجعة والنشر والنسخ

المحتوى المنشور يجب أن يكون Snapshot ثابتة وغير قابلة للتعديل. كل تعديل بعد النشر ينشئ مسودة جديدة.

### التدفق

1. إنشاء أو تحرير مسودة.
2. فحص تلقائي Preflight.
3. إرسال للمراجعة.
4. ملاحظات واعتماد/رفض.
5. نشر فوري أو مجدول.
6. مراقبة النشر.
7. إلغاء نشر أو Rollback عند الحاجة.

### فحص Preflight

افحص قبل النشر:

- الروابط المكسورة أو الأهداف غير النشطة.
- نقص الترجمة.
- صور بلا Alt.
- تباين الألوان.
- Overflow على المقاسات الأساسية.
- عناصر بلا Tracking key.
- تعارض Routes.
- مكونات غير مدعومة.
- حملات منتهية أو دولة غير متوافقة.
- أصول غير مصرح بها.
- بيانات ديناميكية لا تعيد نتيجة.
- تأثير تعديل Header/Footer على الصفحات المشتركة.

النشر عملية ذرية: إما تنشر النسخة كاملة أو تبقى النسخة السابقة. إذا فشل النشر، لا تظهر صفحة نصف محدثة. يجب أن يبقى آخر إصدار منشور صالحًا للعرض حتى إصلاح المشكلة.
## 16. نظام التتبع الموحد

أنشئ Tracking SDK داخليًا موحدًا في المشروع بدل استدعاءات مشتتة داخل كل مكون. كل حدث له تعريف وإصدار وحقول مسموحة.

### مبادئ القياس

- لا تسجل كل حركة فأرة أو ضغطة لوحة مفاتيح.
- سجّل فقط الأحداث ذات القيمة التشغيلية أو التجارية.
- لا تستخدم Fingerprinting أو تتبعًا عبر مواقع أخرى.
- لا تعتبر النقر على رقم الجوال مكالمة ناجحة.
- لا تعتبر فتح نموذج التواصل طلبًا مرسلًا.
- لا تعتبر إضافة منتج للسلة عملية شراء.
- أحداث الطلب والدفع النهائية تأتي من الخادم ووحدة الطلبات، لا من المتصفح.
- خزّن الوقت خادميًا في UTC، واعرضه حسب المنطقة المناسبة للمستخدم.

### كتالوج الأحداث الأساسي

#### العرض والتصفح

- `page_view`
- `section_impression`
- `promotion_impression`
- `listing_card_impression`
- `product_card_impression`
- `store_card_impression`
- `scroll_depth_25/50/75/100`
- `engaged_time_bucket`

لا يحتسب Impression إلا بعد ظهور نسبة مناسبة من العنصر لمدة زمنية معقولة، مثل 50% لمدة ثانية، مع جعل القاعدة مركزية قابلة للتعديل.

#### التفاعل مع المحتوى

- `button_click`
- `navigation_click`
- `tab_select`
- `carousel_interaction`
- `search_submit`
- `filter_apply`
- `campaign_click`
- `internal_link_click`
- `external_link_click`

#### السوق والهوية

- `listing_view`
- `product_view`
- `store_view`
- `favorite_add`
- `favorite_remove`
- `share_open`
- `copy_link`
- `rfq_start`
- `rfq_submit`

لا تحاول معرفة التطبيق الذي اختاره المستخدم من Share Sheet إذا لم يسمح النظام بذلك. يمكن قياس فتح المشاركة، نسخ الرابط، ومصدر الزيارة اللاحقة عند توفر Referrer/UTM بشكل مشروع فقط.

#### التواصل

- `contact_options_open`
- `phone_reveal`
- `phone_click`
- `call_request_start`
- `call_request_submit`
- `message_request_start`
- `message_request_submit`
- `contact_request_accepted`
- `contact_request_declined`

سمِّ `phone_click` في التقارير «ضغطات على رقم الاتصال» أو «محاولات اتصال»، ولا تسمّه «مكالمات تمت». لا تخزن رقم الجوال داخل الحدث.

#### التجارة — عند التفعيل فقط

- `add_to_cart`
- `remove_from_cart`
- `cart_view`
- `checkout_start`
- `order_submit`
- `order_confirmed`
- `order_cancelled`
- `order_fulfilled`

هذه الأحداث تظهر فقط في سوريا ولبنان والأردن والعراق ومصر، وفقط عندما تكون وحدة المتاجر والسلة والطلبات منفذة ومفعلة فعليًا لذلك السوق. هذه المرحلة **لا تبني السلة أو الدفع أو الطلبات من الصفر**؛ تنشئ نقاط التكامل والتحليلات، وتبقيها Dormant خلف Feature Flag إلى أن توجد الوحدة الحقيقية.

#### أحداث النظام والجودة

- `content_publish_success/failure`
- `campaign_start/end/pause`
- `analytics_ingest_rejected`
- `analytics_batch_failure`

أحداث الجودة الإدارية لا تختلط بأحداث الزوار ولا تظهر لصاحب الإعلان.

## 17. بنية حدث التتبع

بعد مراجعة البنية الحالية، اجعل كل حدث يحتوي على أقل قدر لازم، مثل:

- `event_id` فريد لمنع التكرار.
- `event_name` من الكتالوج فقط.
- `event_schema_version`.
- `occurred_at` من العميل ضمن حدود معقولة.
- `received_at` من الخادم.
- Session مجهولة First-party قابلة للدوران.
- `user_id` اختياري إذا كان المستخدم مسجلًا.
- الهوية النشطة للزائر عند الحاجة الداخلية، من دون كشفها لصاحب المحتوى.
- `country_id` و`city_id` المسموحان.
- `page_id` و`page_version_id` و`block_id`.
- `campaign_id` و`creative_id` و`placement_id`.
- نوع الهدف ومعرفه: إعلان/منتج/متجر/صفحة/تصنيف.
- المالك الفعلي للهدف الذي يحله الخادم، لا الذي يرسله العميل.
- Referrer domain فقط بعد تنظيفه.
- UTM allowlist بعد التنظيف.
- نوع الجهاز/المقاس بشكل مجمع.
- خصائص إضافية JSONB ضمن Allowlist وحجم محدود.
- `is_test` و`is_internal_traffic` ونتيجة فحص Bot.

ممنوع داخل الحدث:

- كلمة مرور أو OTP أو Token.
- رقم جوال أو بريد كامل.
- محتوى رسالة أو محادثة.
- نص مستند أو فاتورة أو هوية.
- IP خام دائم التخزين.
- موقع GPS دقيق.
- Query string قد يحتوي أسرارًا.
- User-Agent خام طويل إذا كان الجهاز المصنف يكفي.

## 18. استقبال الأحداث والتحقق منها

أنشئ نقطة استقبال خادمية واحدة أو مسارًا موحدًا مناسبًا للبنية الحالية، مثل Edge Function، مع الالتزام بما يلي:

- قبول Batch صغير من الأحداث بدل طلب لكل نقرة.
- Schema validation صارم.
- CORS مقيد بأصول المنصة.
- Rate limit حسب الجلسة/المستخدم/الأصل.
- حد لحجم Body وعدد الأحداث.
- التحقق من `event_name` والحقول المسموحة.
- تجاهل أو رفض التوقيت غير المنطقي.
- توليد/تأكيد `received_at` خادميًا.
- Deduplication بواسطة `event_id`.
- حل مالك الإعلان/المنتج/المتجر خادميًا من السجل الحقيقي.
- منع العميل من كتابة `tenant_id` أو Owner attribution كما يريد.
- عدم منح `anon` أو `authenticated` وصول INSERT مباشر لجدول الأحداث الخام.
- تسجيل فشل الاستقبال بصورة منقحة لا تحتوي Payload حساسًا.

استخدم Queue محلية قصيرة في العميل مع Batch وRetry محدود للأحداث غير الحساسة. لا تجعل فشل التتبع يعطل فتح الصفحة أو الإضافة للسلة أو إرسال الطلب. عند إغلاق الصفحة يمكن استخدام وسيلة إرسال مناسبة للمتصفح من دون تكرار الحدث.

الأحداث التي تمثل نتيجة حقيقية—مثل إنشاء طلب، قبول تواصل، تأكيد طلب أو إلغائه—تسجل من الخادم عند نجاح العملية الفعلية، لا من Click handler.

## 19. تعريف المقاييس ومنع التضليل

أنشئ Data Dictionary داخل لوحة التحليلات يشرح كل مقياس:

- المشاهدات الكلية.
- الجلسات الفريدة التقديرية.
- مرات الظهور.
- النقرات.
- معدل النقر CTR.
- زيارات التفاصيل.
- المفضلة.
- محاولات الاتصال.
- طلبات التواصل المرسلة.
- طلبات التواصل المقبولة.
- الإضافة للسلة.
- بدء إتمام الطلب.
- الطلبات المنشأة/المؤكدة عند وجود الوحدة.
- Conversion rate مع توضيح البسط والمقام.

لا تستخدم كلمة «أشخاص فريدون» إذا كانت التقنية تقيس Sessions أو Browsers فقط. وضّح الفرق بين Total وUnique estimate. اعرض وقت آخر تحديث والمنطقة الزمنية ونطاق التاريخ والفلاتر المؤثرة.

## 20. تحليلات مدير المنصة

أضف مركز تحليلات شامل داخل لوحة القيادة السابقة.

### نظرة عامة

- الزيارات والجلسات والتفاعل عبر الزمن.
- الصفحات الأكثر زيارة.
- الأقسام والأزرار الأعلى تفاعلًا.
- أداء الصفحة الرئيسية حسب نسخة المحتوى.
- أداء الدول والمدن والتصنيفات.
- الإعلانات والمتاجر والمنتجات الأعلى مشاهدة أو تفاعلًا.
- محاولات الاتصال وطلبات التواصل.
- Funnel من الظهور إلى العرض ثم التواصل/السلة/الطلب.
- أداء الحملات والمواضع والـCreatives.
- مصادر الزيارة والقنوات عند توفرها بصورة مشروعة.
- الأجهزة والمقاسات واللغة.

### تحليلات المحتوى

- مقارنة نسختين منشورتين من الصفحة.
- أداء كل `block_id`.
- نسبة ظهور القسم ونسبة النقر.
- Scroll depth ووقت التفاعل المجمع.
- روابط لا ينقر عليها أحد.
- أزرار عالية النقر لكن منخفضة التحويل.
- صفحات خروج مرتفعة، مع عدم الجزم بالسبب من الرقم وحده.

### تحليلات الحملات

- Impressions وUnique sessions.
- Clicks وCTR.
- زيارات الهدف.
- محاولات التواصل أو السلة أو الطلب المنسوبة للحملة.
- الأداء حسب Creative وPlacement ودولة ومقاس.
- مقارنة الفترة والنسخ.
- حملات لم تبدأ، لم تستقبل ظهورًا، أو هدفها موقوف.

### جودة البيانات

- نسبة الأحداث المقبولة والمرفوضة.
- الأحداث المكررة.
- الأحداث غير المعروفة.
- تأخر التجميع.
- أحداث بلا Target صالح.
- تغير مفاجئ في الحجم.
- حركة Bot أو داخلية مستبعدة.
- الصفحات أو المكونات التي لم تركب عليها أحداث صحيحة.

لا تعرض Raw event explorer واسعًا إلا لصلاحية تقنية محددة، مع إخفاء كل معرف شخصي، ولفترة قصيرة، ولغرض تشخيصي مسجل.

## 21. تحليلات صاحب المتجر أو الإعلان

أضف شاشة «الإحصاءات» داخل الحساب/المنشأة النشطة. يجب أن تكون أبسط من لوحة المدير وأكثر وضوحًا.

### البطاقات الأساسية

- مرات ظهور الإعلانات أو المنتجات.
- زيارات التفاصيل.
- زيارات المتجر/الملف.
- ضغطات التواصل.
- ضغطات رقم الاتصال.
- طلبات الرسائل أو التواصل المرسلة.
- إضافات للمفضلة.
- مشاركات ونسخ الرابط.
- إضافات للسلة والطلبات عندما تكون الوحدة مفعلة.
- معدل التحويل مع تعريفه.

### التحليلات التفصيلية

- منحنى زمني للفترة المختارة.
- Funnel واضح: ظهور → فتح → تواصل أو سلة → طلب.
- أفضل الإعلانات/المنتجات.
- المدن والدول بصورة مجمعة.
- نوع الجهاز.
- مصادر الزيارة العامة.
- أيام وأوقات النشاط.
- مقارنة بالفترة السابقة.

### قواعد العزل والخصوصية

- يرى صاحب الهوية النشطة سجلاته فقط.
- عضو المنشأة يحتاج عضوية فعالة وصلاحية تحليلات.
- تغيير الهوية يمسح Cache واستعلامات الهوية السابقة ويعيد التحميل.
- لا يقبل API `owner_id` أو `tenant_id` من العميل كمصدر ثقة؛ يحله الخادم من الجلسة والهوية النشطة والعضوية.
- لا تظهر أسماء الزوار أو حساباتهم أو أرقامهم أو جدولًا لزيارات فردية.
- إذا أرسل الزائر رسالة أو طلبًا أو طلب شراء، تظهر بياناته فقط داخل وحدة الرسالة/الطلب حسب صلاحياتها، لا بسبب لوحة التحليلات.
- أخفِ أو اجمع الشرائح الصغيرة جدًا، مثل أقل من 5 جلسات، تحت «أخرى» لمنع الاستدلال على شخص واحد.
- استبعد زيارات صاحب المحتوى وموظفيه من الأرقام الافتراضية، مع توضيح ذلك.

## 22. التحليلات فوق لوحة الرسم

أضف وضعًا اختياريًا داخل محرر الصفحة باسم «عرض الأداء»:

- يضع Badge صغيرة على كل Section/Block تعرض Impressions وClicks وCTR للفترة.
- يستخدم تدرجًا لونيًا بسيطًا لإبراز الأعلى والأقل تفاعلًا.
- يدعم اختيار نسخة منشورة وفترة ودولة ومقاس.
- يفتح التفاصيل عند الضغط على المكون.
- لا يعرض حركة فأرة حقيقية أو تسجيل جلسة أو بيانات زائر فردي.
- لا يسمح بتعديل النسخة المنشورة أثناء وضع الأداء؛ إنشاء تعديل ينتج مسودة جديدة.

هذا يحقق فكرة «أرسم الصفحة وأرى نتيجة كل جزء» من داخل نفس الاستوديو.

## 23. الإسناد Attribution

ابدأ بإسناد بسيط ومفهوم وقابل للتدقيق:

- اربط كل Impression/Click بالصفحة والنسخة والمكون والحملة والهدف.
- داخل الجلسة نفسها، احتفظ بأول مصدر وآخر مصدر معروفين بصورة منفصلة.
- اعرض Direct عندما لا يوجد مصدر موثوق، ولا تخمّن.
- لا تنفذ Cross-device identity stitching.
- لا تدّعِ معرفة التطبيق المختار من Share Sheet.
- Conversion الخادمي يرتبط بالحملة فقط إذا حملت الجلسة معرف Attribution صالحًا ضمن نافذة زمنية واضحة وقابلة للإعداد.
- وثق نافذة الإسناد وطريقة الحساب في Data Dictionary.

## 24. الخصوصية والامتثال

ابنِ القياس First-party وبأقل بيانات ممكنة:

- معرف جلسة مجهول وقابل للدوران، لا Fingerprint دائم.
- احترام تفضيلات الخصوصية والموافقة حسب السوق والسياسة القانونية.
- عدم تخزين IP الخام؛ استخدمه لحظيًا للحماية أو اشتقاق موقع تقريبي إذا كان ذلك مسموحًا ثم تخلص منه.
- تنظيف Referrer والـUTM.
- عدم تسجيل نصوص الحقول أو كلمات البحث الحساسة بلا سياسة واضحة.
- صفحة توضح للمستخدم أنواع القياس الأساسية وخياراته عند الحاجة.
- Retention policy للأحداث الخام والملخصات، قابلة للإدارة بصلاحية عليا ومسجلة.
- دعم طلبات الحذف/التقييد وفق السياسة من دون إفساد الأرقام التاريخية؛ استخدم Aggregates مجهولة عند الإمكان.
- لا ترسل بيانات التحليلات إلى صاحب متجر آخر أو خدمة خارجية غير معتمدة.

## 25. نموذج البيانات المنطقي

افحص الموجود أولًا. إذا لم توجد بنية مكافئة، استخدم أقل مجموعة ممكنة بأسماء تتماشى مع المشروع. النموذج المقترح منطقي وليس أمرًا لإنشاء أسماء مكررة:

### المحتوى

- `cms_pages`
- `cms_page_versions`
- `cms_publications` أو مؤشر النسخة المنشورة داخل الصفحة.
- `cms_navigation_sets`
- `cms_navigation_versions`
- `cms_campaigns`
- `cms_campaign_creatives`
- `cms_placements`
- `cms_redirects`
- `cms_assets` أو الربط بمكتبة الوسائط القائمة.

احتفظ بتخطيط كل نسخة كـJSONB Versioned وValidated يحتوي Blocks ذات IDs ثابتة، مع Metadata منفصلة للبحث والحالة والمسار والمالك. لا تستخدم JSONB لتخزين حقول تحتاج FK أو فلاتر ثابتة إذا كان العمود الصريح أنسب.

### التحليلات

يفضل وضع الأحداث الخام في Schema خاص غير مكشوف إن سمحت البنية، مثل:

- `analytics.event_definitions`
- `analytics.events_raw`
- `analytics.daily_metrics`
- `analytics.hourly_metrics` عند الحاجة.
- `analytics.ingestion_failures` ببيانات منقحة.
- `analytics.retention_runs`.

استخدم مفتاحًا داخليًا متسلسلًا مناسبًا للأحداث كبيرة الحجم، و`event_id` فريدًا خارجيًا لمنع التكرار. أضف قيودًا على `event_name` ونسخة الـSchema والقيم المطلوبة، وفهارس على كل Foreign Key وعمود مستخدم في RLS.

### الأداء

- استخدم Batch inserts للأحداث.
- استخدم Cursor pagination للقوائم العميقة، لا OFFSET العميق.
- صمم Composite indexes وفق الاستعلامات الفعلية: الهوية + التاريخ + الحدث، الصفحة + النسخة + التاريخ، الحملة + التاريخ.
- استخدم Partial indexes للحالات النشطة أو الفاشلة عند وجود نمط استعلام ثابت.
- يمكن استخدام BRIN للوقت في جدول أحداث كبير متزايد زمنيًا بعد اختبار الخطة.
- لا تنفذ Partitioning مبكرًا. استخدمه عندما يثبت الحجم والحاجة التشغيلية، مثل جداول زمنية ضخمة تقارب 100 مليون صف أو حاجة حذف زمني سريع.
- استخدم GIN على JSONB فقط إذا كانت الاستعلامات تستخدم Containment فعليًا؛ لا تفهرس JSONB كاملًا لمجرد وجوده.
- أنشئ Aggregates ساعية/يومية Incremental بدل فحص الأحداث الخام لكل بطاقة.
- افحص `EXPLAIN (ANALYZE, BUFFERS)` على بيانات اختبار ممثلة للاستعلامات الثقيلة.

## 26. سياسات RLS والوصول

### المحتوى العام

- `anon` والمستخدم المسجل يقرآن فقط النسخة المنشورة الحالية والفعالة والمناسبة للدولة/الجمهور.
- المسودات والنسخ السابقة لا تظهر في Data API العام.
- رابط المعاينة يستخدم Token محدود المدة والنطاق ولا يحول المسودة إلى عامة.

### إدارة المحتوى

- القراءة والكتابة حسب صلاحيات موظفي المنصة التفصيلية.
- `UPDATE` له `USING` و`WITH CHECK` مع سياسة `SELECT` اللازمة.
- لا يكفي `TO authenticated` وحده؛ يجب شرط صلاحية حقيقي.

### التحليلات

- لا وصول مباشر للأحداث الخام من العميل.
- صاحب المتجر/الإعلان يقرأ Aggregates فقط عبر RPC/View آمنة مقيدة بهويته النشطة وصلاحيته.
- مدير المنصة يقرأ Aggregates حسب صلاحية الإدارة.
- Views تكون `security_invoker = true` عندما تكون في Schema مكشوف، أو توضع في Schema غير مكشوف مع Grants دقيقة.
- إذا كانت `SECURITY DEFINER` ضرورية، توضع في Schema غير مكشوف، مع `search_path` آمن، وفحص `auth.uid()` والصلاحية داخل الدالة، وسحب `EXECUTE` من `PUBLIC/anon/authenticated` ثم منح أقل صلاحية لازمة فقط.
- لف السياسات التي تستخدم `auth.uid()` أو دالة ثابتة داخل `(select ...)` عند ملاءمتها، وأضف فهارس للأعمدة المستخدمة في RLS.

## 27. العرض العام والكاش

- الواجهة العامة تقرأ Published snapshot واحدة، لا مجموعة تعديلات جارية.
- استخدم مفتاح Version للكاش حتى يظهر النشر الجديد بصورة ذرية.
- عند تعطل خدمة المحتوى، اعرض آخر نسخة منشورة صالحة بدل صفحة فارغة.
- Preview يتجاوز الكاش العام بطريقة آمنة ولا يتسرب للزوار.
- التغيير في Header/Footer يبطل الكاش للأسطح المتأثرة فقط.
- لا تجعل حدث التتبع حاصرًا للعرض؛ يعمل بصورة غير متزامنة.

## 28. العربية والإنجليزية والدول

- كل صفحة ومكون وزر وحملة يملك محتوى عربيًا وإنجليزيًا أو حالة نقص ترجمة واضحة.
- RTL/LTR صحيحان في المحرر والمعاينة والصفحة المنشورة.
- لا تنسخ تخطيطًا منفصلًا بلا داعٍ لكل لغة؛ استخدم نفس البنية مع قيم مترجمة، مع السماح باستثناء موثق عند الحاجة.
- دولة الحساب والسوق تبقى حسب القواعد المعتمدة.
- المحتوى والحملات يمكن استهدافها حسب الدولة، لكن المستخدم لا يرى محتوى دولة أخرى افتراضيًا بتغيير URL أو Query.
- السعودية تبقى الدولة الافتراضية للحسابات القديمة حسب القرار السابق.
- السلة والتجارة تظهر فقط في الأسواق الخمسة المحددة وعند Feature Flag فعلي.

## 29. حالات النظام

صمم حالات واضحة لكل شاشة:

- Loading/Skeleton.
- لا توجد صفحات.
- لا توجد نسخة منشورة.
- مسودة غير محفوظة.
- تعارض تحرير.
- فشل التحقق.
- فشل النشر مع بقاء النسخة السابقة.
- حملة بلا هدف صالح.
- لا توجد بيانات تحليلية بعد.
- البيانات تتجمع أو متأخرة.
- صلاحية غير كافية.
- الهوية النشطة لا تملك عناصر قابلة للتحليل.
- Feature غير متاحة في الدولة.

لا تعرض صفرًا وكأنه فشل إذا كانت الفترة لم تستقبل بيانات. فرّق بين 0 و«لا توجد بيانات» و«البيانات متأخرة».

## 30. خطة التنفيذ الهادئة على دفعات

نفذ بالتسلسل التالي، مع اختبار وإغلاق كل دفعة قبل التالية:

### الدفعة 1 — الجرد وخريطة التكامل

- قراءة الأمر السابق وتقارير التدقيق.
- جرد المكونات والمسارات والجداول والصلاحيات.
- تحديد ما سيعاد استخدامه وما ينقص.
- رسم خريطة تدفق المحتوى والحدث والملكية.
- لا تنفذ تغييرات واسعة في هذه الدفعة.

### الدفعة 2 — الأساس الأمني والبيانات

- الصلاحيات الجديدة ضمن النظام السابق.
- نموذج الصفحات والنسخ والنشر والحملات.
- نموذج الأحداث والتجميع.
- RLS/Grants/RPC الآمنة.
- فهارس وقيود محدودة واختبارات SQL.

### الدفعة 3 — محرر الصفحات

- Canvas والمكتبة والخصائص.
- المكونات الأساسية.
- الجوال/التابلت/الكمبيوتر.
- Autosave وUndo/Redo وتعارض التحرير.

### الدفعة 4 — الصفحات والأسطح المشتركة

- إدارة الصفحات والمسارات.
- الهيدر والفوتر والقوائم والتبويبات.
- Design tokens.
- Preview وPreflight.

### الدفعة 5 — الحملات والروابط

- مواضع الحملات.
- ربط إعلان/منتج/متجر/صفحة.
- الجدولة والتعارضات والبدائل.
- دمج التنبيهات مع صندوق العمل السابق.

### الدفعة 6 — استقبال الأحداث

- SDK الموحد.
- Ingestion الخادمي.
- التحقق وRate limit وDeduplication.
- أحداث الخادم الحقيقية.
- وضع الاختبار وجودة البيانات.

### الدفعة 7 — تحليلات مدير المنصة

- النظرة العامة.
- المحتوى والحملات والسوق.
- جودة البيانات.
- وضع الأداء فوق لوحة الرسم.

### الدفعة 8 — تحليلات أصحاب الحسابات

- شاشة الهوية النشطة.
- Funnel والمقارنات والعناصر الأفضل.
- RLS واختبارات تسرب الكيان والدولة.
- التصدير المجمع وفق الصلاحية.

### الدفعة 9 — الخصوصية والأداء والإغلاق

- Retention والخصوصية.
- اختبارات الحجم وEXPLAIN.
- Responsive regression.
- Security advisors وType check وBuild وConsole.
- حذف بيانات الاختبار.
- تقرير الإغلاق، بلا Publish.

إذا ظهر تحذير أمني أو تعارض في قاعدة البيانات، أوقف الدفعة عنده وعالجه منفردًا، ثم اختبره قبل المتابعة. لا تستخدم Ignore issue أو إصلاحًا جماعيًا.

## 31. اختبارات القبول الملزمة

### التكامل مع الأمر السابق

1. الوحدات تظهر داخل مركز القيادة السابق ولا تنشئ لوحة مدير ثانية.
2. تستخدم نفس المستخدمين والصلاحيات وسجل العمليات وصندوق العمل.
3. لا توجد نسخة ثانية من الحساب أو المتجر أو الإعلان أو المنتج أو المشروع.
4. التغييرات لا تكسر مسارات الإدارة السابقة أو السوق أو الحسابات.
5. مدير المنشأة لا يستطيع فتح استوديو محتوى المنصة.
6. موظف المحتوى يرى فقط الصلاحيات الممنوحة له.

### محرر المحتوى والنشر

7. إنشاء صفحة مسودة لا يجعلها عامة.
8. المعاينة تعمل بتصريح محدود ولا تكشف المسودة لزائر عادي.
9. لا يمكن نشر مكون غير معروف أو Payload غير مطابق للـSchema.
10. HTML/Script/XSS لا يمر من Rich Text أو الخصائص أو الروابط.
11. تغيير Slug يمنع التعارض وينشئ Redirect صحيحًا.
12. إلغاء النشر يبقي التاريخ والنسخ.
13. Rollback يعيد نسخة كاملة مع سجل، لا أجزاء منها.
14. فشل النشر يبقي آخر نسخة صالحة.
15. محرران لا يكتبان فوق بعضهما بصمت.
16. Header/Footer المنشوران يظهران بصورة ذرية.
17. زر مربوط بإعلان موقوف لا ينشر أو يتحول للبديل المحدد.
18. حملة منتهية تختفي وتظهر البدائل بلا فراغ.
19. المحتوى المستهدف لدولة لا يظهر في دولة أخرى.
20. الترجمة وRTL/LTR يعملان في المحرر والعرض.

### الأمان والعزل

21. `anon` لا يقرأ المسودات أو النسخ السابقة أو بيانات التحليلات الخاصة.
22. المستخدم المسجل لا يصل للأحداث الخام.
23. صاحب متجر لا يرى إحصاءات متجر آخر بتغيير ID أو URL أو Request body.
24. عضو منشأة بلا `analytics.view` لا يرى التحليلات.
25. تبديل الهوية يمسح Cache وبيانات الهوية السابقة ويعيد التحميل.
26. العميل لا يستطيع تزوير `owner_id` أو `tenant_id` أو Attribution.
27. `TO authenticated` ليس السياسة الوحيدة لأي جدول حساس.
28. UPDATE policies تحتوي `USING` و`WITH CHECK` والسياسة اللازمة للقراءة.
29. لا توجد View مكشوفة تتجاوز RLS.
30. لا توجد دالة حساسة قابلة للتنفيذ من `PUBLIC` دون قصد.
31. لا يوجد Secret أو `service_role` في الواجهة أو Build.
32. مكتبة الوسائط العامة لا تكشف مستندات خاصة.

### دقة التتبع

33. الحدث المكرر بنفس `event_id` يحتسب مرة واحدة.
34. Impression لا يسجل لمكون لم يظهر فعليًا وفق القاعدة.
35. `phone_click` يظهر كمحاولة/ضغطة وليس مكالمة ناجحة.
36. فتح نموذج التواصل لا يساوي إرسال طلب.
37. الطلب/التأكيد يسجل من نجاح الخادم، لا من النقر.
38. Add to cart لا يظهر في دولة أو حساب غير مفعل للتجارة.
39. مشاركة النظام لا تدعي معرفة التطبيق المختار.
40. حركة صاحب المحتوى والإدارة مستبعدة افتراضيًا.
41. Bots والـRate-limit لا يضخمان المقاييس بسهولة.
42. Referrer وUTM منظفان ولا يخزنان أسرارًا.
43. لا يوجد رقم هاتف أو محتوى رسالة داخل الأحداث.
44. الوقت والتاريخ والمنطقة الزمنية موضحة.
45. Total وUnique estimate لا يختلطان.
46. الصفر وغياب البيانات وتأخر التجميع تظهر كحالات مختلفة.

### التحليلات

47. أرقام Manager dashboard تطابق Aggregates واختبار SQL مستقل.
48. أرقام صاحب المتجر تطابق عناصر هويته فقط.
49. Funnel يستخدم تعريفًا موثقًا وثابتًا.
50. مقارنة نسختين تربط الأحداث بـ`page_version_id` الصحيح.
51. نسخ Block ينشئ `block_id` جديدًا.
52. تصدير صاحب المتجر مجمع ولا يحتوي بيانات زائر فردي.
53. الشرائح الصغيرة أقل من الحد لا تكشف هوية ضمنية.
54. Data quality تكشف الأحداث غير المعروفة والمتأخرة.

### الواجهة والتجاوب

55. اختبر 320 و390 و768 و1024 و1366 و1440 بكسل.
56. لا يوجد Overflow أفقي غير مبرر أو قص أو تداخل.
57. سحب المكونات يعمل بالفأرة واللمس ولوحة المفاتيح حيث يلزم.
58. تغيير CSS للجوال لا يكسر الكمبيوتر والعكس.
59. الجداول تتحول لعرض قابل للاستخدام على الجوال.
60. كل زر ظاهر فعلي، وحالات Loading/Empty/Error/Forbidden مكتملة.

### الأداء والإغلاق

61. لا تعتمد Dashboards على فحص الأحداث الخام لكل تحميل.
62. الاستعلامات الثقيلة مفحوصة بـEXPLAIN وIndexes مبنية على النمط الفعلي.
63. Batch ingestion لا يعطل تجربة المستخدم عند الفشل.
64. Type check وBuild ينجحان بلا أخطاء.
65. Console بلا أخطاء جديدة على المقاسات الأساسية.
66. Security وPerformance advisors لا يحتويان Critical/Error غير محلل.
67. بيانات الاختبار حذفت ولا توجد سجلات يتيمة.
68. لم يتم Publish.

3. ما الذي يراه صاحب المتجر أو الإعلان وما الذي لا يراه.
